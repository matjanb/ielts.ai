# Комплексный аудит ielts.camp — 2026-07-03

Многоагентный аудит (6 параллельных агентов: server-crash, client-crash, security,
business-logic, data/concurrency, config/deploy). ~90 находок → ~40 уникальных после
дедупликации. Severity выставлен после ручной верификации ключевых пунктов.

**Общая оценка здоровья: 6/10.** Архитектура здоровая; закрыть надо одну дыру в
безопасности и кластер проблем вокруг денег и грейдинга до роста нагрузки. Почти всё —
точечные фиксы.

## 🔴 CRITICAL

### 1. RLS profiles: любой юзер может выдать себе admin + lifetime (ВЕРИФИЦИРОВАНО)
`supabase/schema.sql:227` + миграции 016/017. Политика `for update using (auth.uid()=id)`
без ограничения колонок; `is_admin`/`lifetime_access` добавлены `add column` без REVOKE/GRANT.
Дефолт Supabase даёт authenticated UPDATE на все колонки.
Эксплойт: `PATCH /rest/v1/profiles?id=eq.<uid> {"is_admin":true,"lifetime_access":true,"free_mock_used":false}` с anon-ключом.
Фикс: `REVOKE UPDATE ON profiles FROM authenticated;` затем
`GRANT UPDATE (full_name, avatar_url, country, target_band_score, current_level, onboarding_completed, preferred_language) ON profiles TO authenticated;`

### 2. TTS-роут без auth — открытый счёт OpenAI (ВЕРИФИЦИРОВАНО, 2 агента)
`app/api/ai/roast/tts/route.ts:12` — нет getApiUser/gateAiRequest (все соседние roast-роуты гейтятся).
Аноним льёт POST {text,mode} до 1000 симв. в tts-1 в цикле.
Фикс: `const gate = await gateAiRequest('roast'); if (gate.error) return gate.error` в начало; не возвращать e.message.

### 3. Таймер экзамена шлёт пустые ответы → band 0 (ВЕРИФИЦИРОВАНО)
`app/(dashboard)/listening/[testId]/page.tsx:2096`. `useCallback(()=>handleSubmit(),[])`
замораживает handleSubmit с answers={}, attemptId=null. По истечении 30 мин TestTimer зовёт замороженную версию.
Фикс: держать актуальный handleSubmit в ref, звать submitRef.current(). (Тот же паттерн для reading.)

## ⚪️ Уточнения (снижают панику)
- **stripe_customer_id vs paddle_customer_id**: НЕ активный баг. Код намеренно совпадает с живой БД
  (миграция 012 НЕ применена, вебхук пишет stripe_customer_id). Платежи работают. Мина рванёт при
  применении 012 или подъёме из schema.sql. Не применять 012 отдельно — только атомарно с правкой кода.
- **CRON_SECRET**: заведён в Vercel prod через CLI. Отсутствует только в локальном .env.local.
- **Ложные срабатывания**: number-words в answer-checking, reading-таблица, 0-day inactivity, >200 attempts окно.
